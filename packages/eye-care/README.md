# 护眼模式（Eye-care mode）

把 DeepSeek Harness Web 界面整体换成暖色纸感配色，降低蓝光观感。

## 用起来

**设置 → 通用设置 → 护眼模式**，打开开关即可。切换即时生效，不需要重启；关掉开关就完全回到内置配色。

开关状态按浏览器保存（`localStorage` 的 `dsh.eye-care.enabled`），和宿主保存「对话宽度」等界面偏好的方式一致。这意味着：换浏览器、换设备、或清掉站点数据后，开关会回到关闭状态——这不是设置丢失，是这个偏好本来就只存在当前浏览器里。

它是在当前「外观」之上叠一层，不冲突：外观选浅色、深色还是跟随系统都照旧，护眼配色会自动跟着当前配色换一套对应的暖色板，不需要重新打开开关。

## 它改了什么

不新建主题，而是往当前主题上叠一层 token 覆盖（`ctx.theme.overrideTokens`），只动颜色，不动字号、字体、布局。覆盖分两类：

- **原始色阶**：宿主那条 `--dsw-static-neutral-*` / `--dsw-static-neutral-bluish-*` / `--dsw-static-blue-*` / `--dsw-static-deepseek-*` 色阶换成暖纸色阶，另把 `--dsw-static-red-600` 压深一档（纸底比纯白暗，原值在纸上只有 4.0:1）。设计系统里绝大多数 `--dsw-alias-*`（背景、正文、边框、侧栏、气泡、链接、发送按钮、代码块……）都是对这些原始色的引用，换掉色阶就等于整体换肤。
- **字面量别名**：边框透明度、遮罩、菜单表面、交互态洗色、JSON 树、文件 diff 底色、代码高亮（`--shiki-*`）这些不引用色阶的 token 逐个给值。另外单独给 `--dsw-alias-state-warn-label`（警示文字在纸色上需要更深）和 `--dsw-alias-label-on-color`（压在填充色上的文字，深色配色需要深墨）。

对比度（与宿主原配色的量级对照）：

| | 本插件 | 宿主 |
|---|---|---|
| 浅色 主文 / 次要 / 三级 | 17.7 / 6.9 / 3.8 | 17.5 / 6.8 / 3.7 |
| 深色 主文 / 次要 / 三级 | 16.1 / 10.2 / 7.1 | 17.5 / 12.1 / 8.5 |

## 边界

- 只覆盖 Web 界面（含桌面客户端里的 Web 视图）。macOS 原生窗口材质、系统滚动条、系统菜单不受影响。
- 侧栏终端的**背景**会跟着变暖（它读 `--dsw-alias-bg-base`），但 xterm 的 16 色 ANSI 调色板是终端自带的，不在这层 token 里。
- 语义状态色（成功绿、错误红、完成紫）**完全不覆盖**，沿用宿主原值，色相自然保留；只把警告文字压深一档，因为宿主那个琥珀在纸底上当文字用会掉到 2.8:1。
- 浅色下减蓝有限：底色从纯白换成米色，B/R 通道比只从 1.00 降到 0.92，主要是暖色相带来的观感变化，不是光谱层面的减蓝。深色下减蓝明显（B/R 从 1.10 降到 0.58）。

## 实现

- `index.js`：Host 半边，空的 `apply` —— 这个插件纯浏览器侧，Host 行只为让 `dsh.client` 把浏览器半边下发给页面。
- `client.js`：浏览器半边。注册设置行 + 用 `ctx.theme.overrideTokens()` 挂/撤覆盖层；`ctx.effect` 保证插件卸载时撤层、撤样式表。开关控件按宿主 `Switch` 的尺寸与 token 实现（36×20，滑块 16px，开启态用 `brand-primary`）。
- `cordis.patch.yml`：插入 `eye-care` 这一行。
- `tests/smoke.mjs`：本地冒烟测试（假 DOM + 假 ctx），验证注册、开关幂等、卸载清理，并拿 `tests/host-tokens.css`（从宿主主题样式表与前端产物导出的 token 名快照）校验每个覆盖名都真实存在——名字写错不会报错、只会静默失效，所以这条断言是必要的。

卸载插件或关掉开关都不会留下残留样式。
